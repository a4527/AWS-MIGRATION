## 작업과 범위

- 사용자 요청에 따라 기존 문서 파일명·번호·Day별 이력을 유지하며 문서 체계를 정리했다.
- [문서 안내](../../AGENTS.md#문서-책임), [문서 관리](../../AGENTS.md#갱신-규칙), [현재 상태](../PROGRESS.md), [기존 결정 탐색](../DECISIONS.md)을 추가하고 루트 README·AGENTS에서 연결했다.
- [TASKS](../TASKS.md)에 기존 완료 표기의 범위와 실제 실행 결과를 확인할 VERIFY-01/02의 선행 조건·수용 기준을 추가했다.
- [마이그레이션](../design/MIGRATION.md), 로드맵·배포·검증 문서의 책임을 명시하고 Terraform 소개의 오래된 예정 표기를 코드 정의와 대조해 수정했다.
- AWS 진단은 기존 런북으로 연결하고 새 ADR·상세 설계·제안·작업 기록의 최소 작성 항목과 생명주기를 정의했다. 기존 기술 선택의 승인 상태는 새로 부여하지 않았다.

## 검증 조건·결과

- 문서와 관련 Terraform 선언을 읽어 Route53/ACM 조건부 구성, CloudWatch, file processor 모듈 존재를 확인했다. 리소스 배포 성공을 검증한 것은 아니다.
- 변경·신규 문서 15개에서 상대 링크 134개의 대상 파일·제목 앵커를 검사했고 모두 통과했다. 제목을 고친 두 절은 기존 앵커를 명시적으로 보존했다.
- `git diff --check`를 통과했다. 신규 문서에서도 줄 끝 공백과 파일 끝 개행을 별도로 확인했다.
- 애플리케이션 코드와 인프라 코드를 변경하지 않았다. 백엔드 테스트·Compose 실행·Terraform validate/apply·AWS API 호출·장애 주입·성능 시험은 수행하지 않았다.

## 문제와 후속 작업

- 기존 Day 13 체크리스트는 완료 표시지만 작업일지는 검증 절차 작성과 실제 AWS 실행을 분리한다. 완료 이력을 보존하고 [현재 상태](../PROGRESS.md)와 후속 검증 작업에서 범위를 명시했다.
- 실제 백신·DB 상태 동기화와 운영 보강 후보는 기존 범위를 유지한다. 구현 완료·일정·새 승인으로 기록하지 않았다.

## 문서 대조

- 요구사항·API·DB 계약, 기존 결정 원문과 Day별 완료 표기는 보존했다.
- 기준 계약·실행 절차·실행 결과의 책임을 구분하고 실제 AWS 검증 성공으로 읽힐 수 있는 상태 해석을 보완했다.
- 실제 AWS 검증 결과는 이번 정리의 확인 범위 밖이며 VERIFY-01/02에서 추적한다.

## CICD-01 PR·이미지 검증 구현

### 작업과 범위

- `다음 진행하자` 요청에 따라 TASKS의 다음 순서를 확인했다. PORT-01의 AWS 인증·비용·보존 조건은 아직 미정이므로 이를 확인하는 질문을 남기고, 독립 착수가 가능한 CICD-01을 진행했다. AWS API 호출·리소스 생성·배포는 수행하지 않았다.
- `.github/workflows/backend-ci-cd.yml`에 main 대상 PR 검증을 추가했다. `test` → `image` → `deploy` 의존 관계로 테스트 후 Docker 이미지를 빌드하고 Trivy로 검사한다. HIGH/CRITICAL은 수정 버전 유무와 관계없이 차단하며 검사 자체의 오류도 실패로 처리하도록 설정했다. 예외는 등록하지 않았다.
- workflow 기본 OIDC 권한을 제거하고 배포 job에만 `id-token: write`와 AWS role 참조를 남겼다. checkout의 자격 증명 보존을 껐다. 수동 배포는 main으로 제한했다.
- 수동 main 실행은 검사 이미지를 1일 artifact로 전달해 배포 job에서 load/tag/push한다. 배포 단계의 재빌드를 제거했다. 환경 간 digest 승격·승인과 smoke 검증은 CICD-02의 남은 범위다.
- [배포 기준](../design/DEPLOYMENT.md#5-cicd)에 차단 기준·예외 검토·실행 확인 조건을 기록했다. 설정은 [Trivy 공식 안내](https://github.com/aquasecurity/trivy-action#usage)와 [GitHub job 권한 기준](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idpermissions)을 확인했다. Trivy action v0.36.0 태그가 가리키는 commit SHA로 고정했다.

### 검증과 한계

- actionlint 1.7.12로 `.github/workflows/backend-ci-cd.yml`을 검사해 통과했다. 작업 도구는 `/tmp/aws-migration-ci-tools`에만 준비했다.
- 로컬 Java 미설치로 임시 Temurin JDK 17을 준비했다. `backend/`에서 `JAVA_HOME=/tmp/aws-migration-ci-tools/jdk GRADLE_USER_HOME=/tmp/aws-migration-ci-tools/gradle ./gradlew test --no-daemon`을 실행해 BUILD SUCCESSFUL을 확인했다. JUnit XML 집계: 9개, 실패 0개, 오류 0개, 건너뜀 0개. postgres 프로필 테스트는 H2 PostgreSQL 호환 모드이며 실제 Aurora 연결 검증이 아니다.
- Docker CLI가 WSL integration 미설정 메시지를 반환해 로컬 이미지 빌드·Trivy 실검사는 수행하지 못했다. GitHub Actions도 실행하지 않았다. 정상 PR과 의도적 테스트 실패·빌드 실패·취약점 검출에서 실제 job 차단을 확인하고 run 링크를 보완해야 CICD-01을 완료할 수 있다.
- 원격 ruleset/branch protection을 변경하지 않았다. PR 검사 실행과 병합 강제 차단은 구분하며 필수 검사·문서 전용 PR 처리는 배포 기준에 남겼다.

### 문서 대조

- CICD-01 수용 기준과 workflow의 의존 관계·검사 설정·권한을 대조했다. TASKS는 구현·정적 검증과 실제 실행 검증 대기를 구분하고 PROGRESS에 현재 범위를 반영했다. PRD·API·DB 계약과 기존 기술 결정은 변경하지 않았다.
- 기존 문서 통합의 미커밋 변경을 보존했다. 제품 API 동작을 바꾸지 않아 CHANGELOG에는 기능 변경을 추가하지 않았다.

- 최종 확인: 저장소 Markdown 상대 링크 140개에서 파일·앵커 오류 0개, `git diff --check`와 actionlint 검사를 통과했다. VERIFY-01/02·PORT-01 및 CICD-01의 원격 실행 미확인 상태를 완료로 바꾸지 않았다.
