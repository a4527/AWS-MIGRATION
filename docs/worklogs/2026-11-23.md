## PR #7 머지와 drift 오탐 수정

- 조건: 실습 계층(`dev`) 없음, 유지 계층(`dev-data`)만 유지. PR #7(3단계 후속 수정)을 00:00Z에 머지.
- 머지 후 Terraform workflow: 정적 검사, 두 계층 plan 성공. 실습 계층이 없어 apply 건너뜀.
- 발견: 11-21, 11-22 정기 drift 검사가 `drift (dev-data)`에서 실패.
  - 로컬 `plan -refresh-only -detailed-exitcode` 결과 exit 2. 바뀐 것으로 나온 항목은 2개다. Aurora 보안 그룹의 "PostgreSQL from application" ingress 규칙과 private route table의 `0.0.0.0/0 → NAT` 경로가 사라진 것으로 표시됐다.
  - 둘 다 실습 계층이 별도 리소스로 더했다가 11-20 destroy로 지운 것이다. 실제 drift가 아니다.
  - 같은 계층의 일반 `plan -detailed-exitcode`는 exit 0이다.
- 수정: drift 검사를 일반 plan으로 바꾸고, 바뀐 리소스 목록을 job 로그에도 출력한다. 근거는 [TROUBLESHOOTING](../TROUBLESHOOTING.md#정기-drift-검사가-유지-계층에서-매일-실패함)에 적었다. DEC-019 본문과 [DEPLOYMENT 4.1-2](../design/DEPLOYMENT.md) 표를 갱신했다.
- 판단: drift 검사는 "코드로 되돌려야 할 차이"만 알려야 한다. 계층 사이에 공유하는 리소스(SG, route table)에서는 `-refresh-only`가 실습 계층을 올리고 내릴 때마다 오탐을 낸다. 알람이 늘 울리면 진짜 drift를 놓친다.

## drift 검사의 빈틈과 후속 작업 등록

- 일반 plan으로 바꾼 뒤 남는 한계를 정리했다. 별도 리소스로 붙이는 보안 그룹 규칙과 route는 어느 계층의 drift 검사로도 잡히지 않는다.
- 이 빈틈은 CloudTrail 이벤트 → EventBridge → SNS 알림으로 메우기로 하고 SEC-03으로 등록했다. 근거는 [TROUBLESHOOTING](../TROUBLESHOOTING.md#drift-검사가-별도-리소스로-붙인-보안-그룹-규칙을-잡지-못함)에 적었다.

- 조건: 로컬 WSL2, Java 없음(`eclipse-temurin:17-jdk` 컨테이너로 빌드·테스트). AWS 실습 계층 없음.
- 버전 선택: Spring Boot 4.1.3(Spring Framework 7.0.11, Security 7.1.3, Hibernate 7.4.15, Jackson 3.1.8, Tomcat 11.0.27). 4.1.3과 4.2.0이 같은 날(2026-11-19) 나왔다. 수용 기준(Framework 7.0.9 이상)을 만족하는 4.1 패치 계열을 골랐고, 첫 마이너 릴리스인 4.2.0은 고르지 않았다. Gradle wrapper는 8.10.2 → 8.14.3(Boot 4 최소 요구 8.14).
- 코드 변경:
  - `spring-boot-starter-web` → `spring-boot-starter-webmvc`. 테스트는 `spring-boot-starter-webmvc-test`, `spring-boot-starter-security-test`, `spring-boot-resttestclient`·`spring-boot-restclient`(TestRestTemplate)를 추가했다. `@AutoConfigureMockMvc`·`TestRestTemplate` 패키지가 바뀌었고 TestRestTemplate에는 `@AutoConfigureTestRestTemplate`가 필요하다.

  - Tomcat·Netty·Jackson·PostgreSQL JDBC·httpclient5 패치 버전 덮어쓰기를 지웠다. Boot 4.1.3 BOM 버전으로 Trivy가 깨끗하다. MinIO 전이 의존성 3개 고정은 남겼다.
