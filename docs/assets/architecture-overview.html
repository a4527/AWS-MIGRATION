File Share API 아키텍처

파일 공유 API를 온프레미스(Docker Compose)에서 AWS(ECS Fargate)로 옮기는 프로젝트입니다. 원칙은 기능은 그대로 두고 인프라만 교체입니다. 애플리케이션은 도메인별 패키지 안을 계층으로 나누고, 저장소·DB·캐시는 인터페이스(포트) 뒤에 숨겨 Spring 프로필로 구현체를 바꿉니다.

도메인과 JPA Entity 분리

이 프로젝트는 도메인 모델(FileMetadata)과 JPA Entity(FileMetadataEntity)를 별도 클래스로 둡니다. 아래 그림은 현재 방식과, 하나로 합쳤을 때의 흐름을 삭제(markDeleted()) 기준으로 비교합니다.

분리 (현재 구현)

도메인이 JPA 애노테이션·지연 로딩을 모르기 때문에 같은 Service가 InMemory 저장소(기본·테스트)와 JPA 저장소(postgres 프로필)를 그대로 씁니다.

대가: FileMetadataEntity.from()·toDomain() 매핑 코드가 필요하고, 변경 감지 대신 save()를 호출해야 합니다.

통합 (비교안)

클래스와 매핑 코드가 줄고, 트랜잭션 안의 상태 변경이 변경 감지로 자동 저장됩니다.

대가: 도메인 규칙이 JPA 생명주기에 묶여 프로필별 저장소 교체와 순수 단위 테스트가 어려워집니다.

AuthService는 회원가입 값을 받고 LoginResult(사용자·토큰·만료)를 반환합니다. LoginResponse·UserResponse 변환은 AuthController가 합니다.

컨트롤러가 AuthUserPrincipal.toActor()로 common.actor.Actor(사용자 ID·관리자 여부)를 만들어 FileService에 넘깁니다.

5 · 요청 흐름

파일 업로드

메타데이터 조회는 캐시 → DB 순서로 찾은 뒤 소유자 또는 ADMIN인지 확인합니다. 다운로드와 삭제는 캐시를 쓰지 않고 DB 상태로 판단합니다. 삭제는 상태를 DELETED로 바꾸는 논리 삭제이고, 캐시에는 삭제 상태를 덮어씁니다. Redis가 응답하지 않으면 DB로 우회합니다.

  1. Clientmultipart/form-data로 POST /api/files 요청. 재전송 대비 Idempotency-Key 헤더 선택
  2. nginx / ALB백엔드로 프록시. nginx는 client_max_body_size 10m
  3. JwtAuthFilterBearer 토큰 검증 후 AuthUserPrincipal 설정. 컨트롤러가 Actor로 변환
  4. FileUploadService크기 10MB 이하, 확장자 허용목록(pdf, png, jpg, jpeg, txt, csv) 검증
  5. FileStorage객체 위치(UUID)를 먼저 확정. 쓰기 응답이 유실돼도 정리할 수 있게 함
  6. upload_requests키가 있으면 IN_PROGRESS 기록. 완료된 같은 요청은 첫 결과 재전송, 진행 중 409, 다른 요청 422
  7. FileStorage크기를 아는 스트림으로 MinIO 또는 S3에 저장 (전체 버퍼링 없음)
  8. UploadRecorderfiles 저장과 요청 완료를 한 트랜잭션으로. 실패 시 재시도, 끝내 실패하면 기록 없음 확인 후 객체 삭제, 확인 불가면 객체 보존
  9. CacheRedis files:metadata:{id}에 버전 비교 쓰기. 실패해도 업로드는 성공
  10. ControllerApiResponse로 감싸서 응답
  11. Lambda (AWS)S3 ObjectCreated 이벤트로 실행되어 확장자 가드와 메타데이터 태그를 기록하고 CloudWatch에 로그를 남김

배포 책임 분리 (IAC-02)

Terraform은 인프라와 task definition 템플릿을 관리합니다. 서비스가 실행할 revision과 task 수(task_definition, desired_count)는 Terraform 갱신 대상에서 빠져 있고, CD와 Application Auto Scaling이 담당합니다. 템플릿을 바꿔도 실행 중인 서비스에는 자동 반영되지 않습니다.
